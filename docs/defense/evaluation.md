# 糖安食助 · 质量评估（6.5）

> 评估脚本：`backend/scripts/evaluate_quality.py`，在真实 PostgreSQL + Neo4j + Chroma 数据上运行。
> 云 LLM 无 Key，评估时把 `generate` 换成无效内容走模板降级路径，因此响应时间**不含云端调用**。

## 方法

- 20 个用户画像，覆盖糖尿病/普通人群、常见过敏原、忌口，以及妊娠、肾病、未成年三个应拦截边界。
- 每个画像给同一份库存（番茄 + 鸡蛋），统计推荐中的库存利用。
- 规则违反 = 严格结果（strict）里出现含过敏原或忌口食材的食谱。

## 汇总

| 指标 | 结果 | 目标 |
|---|---|---|
| 规则违反率 | 0 / 85 = 0% | 0 |

## 说明

- **规则违反率为 0**：17 个正常画像共 85 个严格推荐里，没有任何一道菜含过敏原或忌口食材。
- **安全拦截正确**：妊娠、肾病、未成年在调用推荐前就被 `safety.yaml` 拦截，返回就医提示，耗时仅 4ms，不经过规则打分、图谱和检索。
- **库存利用与规则协同**：库存统一为「番茄 + 鸡蛋」，多数画像的严格结果里 2 道菜（西红柿炒蛋、番茄豆腐汤）命中了库存。鸡蛋过敏画像的西红柿炒蛋被规则拒绝，库存命中降为 1（只剩番茄豆腐汤），说明过敏原排除优先于库存利用，符合预期。
- **响应时间**：本次为「云 LLM 不可用 → 模板降级」路径，非拦截画像 94~216ms（均值约 134ms）；真实接入云 LLM 后会增加一次网络调用耗时。
