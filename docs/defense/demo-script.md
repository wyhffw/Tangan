# 糖安食助 · 演示脚本

> 目标：10 分钟走完「建档 → 冰箱 → 推荐 → 报告 → 购物清单 → 问答 → 图谱」核心闭环。

## 准备

- 后端已启动：`http://<服务器IP>:8000`（健康检查 `GET /api/v1/health`）。
- 前端已构建：`frontend/dist`，或用 `npm run dev` 启动。
- 演示账号：`demo / demo12345`。

## 流程

| # | 步骤 | 操作 | 预期结果 |
|---|---|---|---|
| 1 | 登录 | 打开前端，用 demo 登录 | 进入首页，鉴权通过 |
| 2 | 建档 | 填身高 170、体重 70、疾病「2型糖尿病」、过敏原「虾」 | 档案保存成功 |
| 3 | 冰箱入库 | 加入「番茄」「鸡蛋」 | 冰箱列表出现两项 |
| 4 | 智能推荐 | 点「推荐」选晚餐 | 给 3-5 道菜，附原因与引用 |
| 5 | 报告解释 | 看日报/周报，点「解释」 | 营养数字由后端算好，LLM 只组织语言 |
| 6 | 购物清单 | 生成清单，勾选，一键入库 | 商品转入冰箱 |
| 7 | 安全拦截 | 问「我胸口疼怎么办」「二甲双胍一次吃多少」 | 固定回复请就医，不调用 LLM |
| 8 | 知识问答 | 问「糖尿病能吃西瓜吗」 | 回答带指南引用 + 免责声明 |
| 9 | 图谱 | 打开知识图谱页，搜「西瓜」 | 展示食材-疾病-食谱关系 |

## 每个步骤的一句话台词

1. 登录：展示 JWT 鉴权，未登录访问聊天接口返回 401。
2. 建档：强调空腹血糖、糖化血红蛋白只记录、不参与推荐计算。
3. 冰箱：入库是后续推荐和购物清单的数据来源。
4. 推荐：七步固定流程，规则过滤 → 图谱打分 → 检索 → 解释 → 事后校验。
5. 报告：所有营养数字由后端计算，LLM 不产出数字。
6. 购物清单：清单按计划自动汇总食材。
7. 安全拦截：调用 LLM 前用关键词拦截，命中直接回复就医提示。
8. 知识问答：结合图谱 + 指南检索，回答末尾附免责声明。
9. 图谱：Neo4j 存储食材-疾病-食谱关系，直观展示推荐依据。
